# Pingo Core Implementation Plan

> **For agentic workers:** Implement inline in this session with test-first cycles. The user's current request authorizes implementation; no separate approval gate is needed.

**Goal:** Deliver a locally runnable FastAPI core that follows DecisionResponse 1.0 and calculates demo scenarios without cloud access.

**Architecture:** Pydantic validates request and response. A pure finance module creates complete installment schedules and window projections. A narrow context provider protocol supplies a clearly labeled own synthetic fixture; real data and Gemini providers are integrated later without silent fallback.

**Tech Stack:** Python, FastAPI, Pydantic, pytest, httpx.

**Spec:** `docs/execucao_v2/PINGO_Execucao_v2/01_ESPECIFICACAO.md` and its `contracts/decision-response.schema.json`.

## Global constraints

- Work only in backend core/API/models and their tests; preserve diagnostic sources and colleague-owned modules.
- `DEMO_MODE=true` is required for fixture responses; real mode must fail explicitly until integrated.
- Do not infer current balance, future obligations, income, commercial terms or loan approval from the 2025 dataset.
- Keep the complete schedule when the projection window ends earlier; preserve exact cents and unknown balance as `null`.

## Tasks

1. Write engine tests for cent distribution, dates, window remainder, missing balance and cashflow ordering. Observe red; implement `backend/core/finance.py`; observe green.
2. Write request validation and API tests for `/health`, `/docs`, needs-input, demo decision, recalculation, duplicate refs and explicit real-mode failure. Observe red; implement Pydantic models, context protocol/fixture provider and handlers; observe green.
3. Validate sample responses against the unchanged JSON schema, run the complete suite, start Uvicorn and exercise both endpoints over HTTP. Record evidence in `docs/STATUS-CORE.md`, usage and pending integration in `docs/DEPLOY_HANDOFF.md`.

## Review focus

- Negative balance is a valid confirmed value, unlike absent balance.
- Upfront cost and installments are each deducted once.
- Duplicate confirmed cashflow refs fail validation.
- Past first due dates and invalid calendar dates do not create a schedule.
- Any cloud/provider error remains visible rather than becoming a demo result.
